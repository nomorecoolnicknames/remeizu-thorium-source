m3note_keystore_profile (device/meizu/m3note/Android.mk, step 5)

Marker file.  The module exists for its LOCAL_POST_INSTALL_CMD: it removes the
keystore.mt6755.so / keystore.mz6755_66_n.so -> libMcTeeKeymaster.so links that
the shared vendor/meizu/m681 module m681_vendor_hal_symlinks creates, and links
the same library as keystore.m681tee.so.

hw_get_module_by_class("keystore") (hardware/libhardware/hardware.c) tries
ro.hardware.keystore first, then ro.hardware / ro.product.board /
ro.board.platform / ro.arch, then "default".  libinit sets
ro.hardware.keystore=m681tee on m681 only, so:
  m681: keystore.m681tee.so -> Trustonic keymaster, as in the m681 donor
        (the A9 daily of 2026-08-24 ran with these links,
        flash-m681-20260928.md §4);
  l681: no keystore module at all -> android.hardware.keymaster@3.0-impl
        falls back to its software keymaster (KeymasterDevice.cpp:70).

FACT (meizu-fleet/flash-l681-20260928.md §14, §17): with the links on l681,
keystore hangs in TrustonicTeeKeymasterImpl's constructor (the m681 Kinibi
keymaster TA does not open on the L681H TEE) on the 3.10 and the 4.4 kernel
alike, and system_server dies at boot phase 600.  Without any keymaster HAL at
all Pie's keystore aborts ("no viable keymaster device found"), so the -impl
stays on both revisions.
